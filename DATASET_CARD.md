**Structure**: Version pairs \((V_{t-1}, V_t)\) labeled as `Benign`, `Risky`, or `Malicious`.

## 3. Phase 3A Dataset Methodology
DriftBench records use the schema documented in `DRIFTBENCH_SPEC.md` and implemented under `driftbench/`.

Each version-pair record must include provenance, license, label rationale, archive paths, timestamps where available, and optional SHA-256 hashes. Records may carry feature and drift vectors after analysis, but Phase 3A does not train models or report performance metrics.

Leakage-safe splits are generated by `extension_id`, not by individual row. This prevents related versions of the same extension from appearing in both train and test splits.

Controlled mutation records are synthetic laboratory artifacts. They must be marked with `controlled_mutation_type` and must not be treated as evidence of real-world prevalence.

## 4. Phase 3B Feature Artifacts
Phase 3B creates extracted feature artifacts from validated records. Raw DriftBench records and extracted features are separate:

- Raw records preserve provenance, labels, version identity, archive paths, and split assignments.
- Feature artifacts preserve metadata columns separately from feature columns.
- Labels and splits are metadata only and are not feature inputs.
- Feature extraction rejects invalid records before extraction.
- Analyzer failures are represented with availability flags instead of silently becoming zeros.
